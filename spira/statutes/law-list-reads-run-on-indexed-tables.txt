A list operation reads an indexed table: the rows it returns are found by an index on the columns it filters and orders by, and the current version of a record is findable without scanning its history. A store whose only path to 'the latest value' is an aggregate over every version ever written is a scan dressed as a lookup, and its cost grows with the store's age, not its size. Scar: 2026-11-03, the control store's range read (GROUP BY key over 424,547 version rows) answered every list in 1.7 s on the imported production store, against the 500 ms budget, and stopped the lifecycle cutover (sp-zjkgeh).
