A blocking edge asserts that one bead CANNOT be done until another is. Never use one to express priority, preference or a running order: the harness already dispatches ready work by priority, so an ordering encoded as edges caps an epic at one worker however many are free, and hides that it is doing so. Set priorities; reserve dependencies for real ones. (2026-09-06: thirty-two unrelated pokedumpster beads were chained head to tail in priority order, so exactly one was ever ready.)
