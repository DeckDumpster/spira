Never rewrite a harness script in place while a process may be executing it — bash reads a script by byte offset as it runs, so an in-place write (an editor save, python open(p,'w'), sed -i) shifts the bytes under a running aeon, sentinel or landing pass and it resumes parsing mid-text when its current command returns. Write the new file beside the old with the mode preserved (cp -p, edit, mv): the running process keeps the old inode, new invocations get the new one, which is what git checkout already does. A mv that drops the exec bit takes every summon down with 203/EXEC. Scar: aeon.sh rewritten in place under three live aeons, then replaced without +x, 2026-09-07.
