## 4.1 Lifecycle and store

| Component | Binaries / units | Purpose, reads and writes |
|---|---|---|
| **Dolt store** | `dolt-beads.service` (`dolt sql-server`, `Restart=always`, refuses manual stop), `dolt-persist.service` (which also prunes the server's temp spool) | The bead store, installed when `SPIRA_DOLT_DATA` is set (persistence units also need `SPIRA_DOLT_DURABLE`). The `watch.store_unit` task alarms the operator if the unit is not active, two minutes after boot and every 15 minutes. |
| **store-persist** | `store-persist restore\|pass [--offline]\|run\|seed --from DIR\|age` | Keeps a RAM-resident Dolt data dir durable: one `dolt backup` per database, restored before the server starts, synced continuously, collected hourly and its copy rebuilt daily by `run`. `age` exits 1 past the lag bound. |
| **beads-store** | `beads-store commit --db P --message M`, `push --db P --remote R` | Commits a beads store's dirty tracked tables through the real `dolt` engine (never `bd`) and verifies the commit cleared the working set. Operator tool; no unit calls it. |
| **lifecycle** | library; `lifecycle/schema.sql`, `migrations/`, `grants.sql` | The bead, delivery, batch, ask and mending machines and the event-log fold. Defines database `spira_lifecycle`; grants make `spira_lc` its only writer. |
| **spira-lc** | `spira-lc` (`serve`, one-shot verbs); `spira-lc.service` (system user) or `lc-serve.service` (same user); scheduler tasks `watch.mend` (2 min), `reconcile.content` (10 min) | The only process that writes `spira_lifecycle`; it refuses a transaction whose applied events on one machine and key do not chain (each `from_state` the previous `to_state`). One JSON argv line in, one JSON line out. Primitives (`show list history event stats facts mending cut stage promote land settle abandon-batch eject-member create-bead create-ask …`), caller verbs (`hold unhold reply release drop supersede certify deliver renew express …`), admin verbs, and the persona-gated `work <bead> <verb>` layer. Also runs the tool verbs (`groom incident sop census queue landing-pass strand hel mender`) as the service user on behalf of dwarves. Reads `SPIRA_LC_SOCKET`, `SPIRA_LC_PASSWORD_FILE`/`SPIRA_LC_USER`. |
| **lifecycle-guard** | `lifecycle-guard [--json] [--gate] [--rules F] <path>...` | Static analyser (shell via tree-sitter, and Rust) refusing any route to lifecycle state around `spira-lc`: `bd close/claim/…`, `bd` status reads feeding a decision, the lifecycle credential outside its owners. No allow-list. A gate fence, not a unit. |
| **bead**, **bdq** | `bead` (shim `spira/bead.sh`), `bdq` | `bead` is the filing contract (`file amend label drop contract lint judge-create event dep …`). `bdq` is the one chokepoint for invoking `bd`: retry on writer-lock contention and create-time fences. |
| **tsd** | `tsd-write`, `tsd-read`, `cert-report`; `tsd-lifecycle-export` | Time-series rows by family (names `[a-z][a-z0-9-]*`). A family with a reader on the landing path is an append-only file `$SPIRA_RUN/tsd/<family>.jsonl`; a family whose readers are all alarms, reports and ops views (`tsd::store::MOVED`) is pushed to the metrics store instead and read back by `tsd-read`, which refuses with a named error when the store is unreachable or holds nothing for the window. `tsd-lifecycle-export` is the sole writer of the `bead-stage` family, projected from the lifecycle event log. |
| **spira-otel** | library | One OTLP span per call, queued (bounded) and pushed by a background thread to the Collector at `SPIRA_OTEL_COLLECTOR_ENDPOINT` as a trace and as a log record; a span it cannot queue or deliver is dropped and counted. Log records appended under `$SPIRA_RUN/otel`; gauge points pushed to `SPIRA_METRICS_ENDPOINT`. Emitting never blocks or fails the caller. |
| **unit-run** | `unit-run watch\|ensure-accounting`; `spira-unit-run-dbus.service` | Learns user-unit executions from the user manager's D-Bus signals and stores one `unit-run-dbus` row per run in the metrics store. |
| **lc-backup** | `spira/lc-backup.sh run\|drill`; `lc-backup.timer` (hourly), `lc-backup-drill.timer` (once daily) | Syncs each lifecycle database through the live server into its local backup dir (`SPIRA_LC_BACKUP_SYNC_DIR`), then uploads to `SPIRA_LC_BACKUP_URL` (`s3://` or `file://`) only the table files not uploaded before, plus a new manifest. The drill restores the newest manifest's file set into a scratch dir and compares row counts. Off-box restore: [Operating](../operating.md#restoring-a-dolt-store-from-its-off-box-backup). |
