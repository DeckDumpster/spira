## Findings

**CPU is not the binding resource.** 7.9 of 16 cores busy, PSI 0, peak memory 1.9G of 11.4G.
Adding more workers would not help.

**Doubling the workers bought 16%, not ~45%.** The effective parallelism _fell_ (7.1x → 7.9x
of double the workers = -0.5 cores' worth of gain). The three longest suites dominate the
critical path and got slower under contention: test-landing +87s, test-poison +63s,
test-requeue-cap +68s. At 16 workers, the gate cannot finish faster than ~414s + overhead
regardless of core count. Shard across VMs is therefore the next horizontal scaling lever —
but the critical path still dominates each VM, so splitting those suites first is cheaper.

**Contention manufactures flakes.** 0 reds at 8 workers; 3 reds at 16, all passing on serial
re-run. More workers make test-testdb-concurrent and suite-cluster tests less reliable.
