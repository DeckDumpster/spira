# §1.114 law-a-rename-repoints-no-reader

Renaming a systemd unit repoints nothing that reads its name. A hardcoded unit name goes on resolving after a rename and silently addresses the unit that still exists, or none — so grep every reader: timer Unit= directives, template instances, INVOCATION_ID self-checks, health probes, and stop/start lists. Derive each from the instance variable with a fallback, so it is correct before a migration and after. After an install that renames units, the first thing to check is whatever reads unit names. Scar: one rename left five readers on the old names — the ops panel reported a running Spira STOPPED and froze its snapshot for an hour, and world.sh stop silently stopped nothing while still slaying live dwarves.
