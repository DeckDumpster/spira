# Part 1 — General

Placeholder Part until the table of contents is approved.

- §1.1 law-absence-needs-a-positive-control — A check that finds nothing must first prove it could have found something.
- §1.2 law-a-watcher-runs-the-sop-before-it-pages — A watcher that detects a condition runs the tool its matching SOP names, records the application, and reports the outcome; it escalates to the Concierge only what no runnable SOP covers, or what the tool could not settle.
- §1.3 law-a-failure-that-will-not-reproduce-is-a-fidelity-gap — A failure that repeats in a round or CI but passes in a reproduction means the reproduction is wrong.
- §1.4 law-p0-express-preempts-lanes — Maintenance lanes never hold capacity a P0 needs: while a P0 or express bead waits unclaimed, no lane dwarf is called, and a waiting P0 express preempts the youngest running lane dwarf through the stop path, which makes its bead true and loses nothing.
- §1.5 law-a-test-that-flips-is-deleted — A test that fails then passes on an unchanged tree is deleted in the same round, not retried or quarantined, and a follow-on bead filed with the deletion adds a deterministic test restoring coverage parity for what it covered; it need not be the same test.
- §1.6 law-an-event-loop-never-blocks — An event loop never blocks: every blocking call it would make, file, socket, process, lock or sleep, is dispatched through a bounded queue to a bounded thread pool, and the loop only awaits the result.
- §1.7 law-a-reconciler-redrives-it-does-not-alarm — A reconciler redrives; it does not alarm.
- §1.8 law-a-p0-in-spira-itself-is-built-by-hand — A P0 defect in Spira's own machinery is built by the Concierge by hand and joins the very next round, cut at once with whatever is certified: it never waits for a batch to fill, and it never lands alone while certified work waits behind it.
- §1.9 law-operator-asked-transcript-reads-are-observation — The Concierge may read any live dwarf's session transcript read-only, asked or not: it is observation, like a status check.
- §1.10 law-doomed-work-is-stopped-fixed-then-resumed — Work the Concierge can see is doomed — a builder rebasing a member its open integration will redo, a round member whose tree cannot pass setup, a bead stacked on a parent that will not land first — is stopped at once: ejected from its round, or slain and held with a manual hold.
- §1.11 law-unit-tests-run-under-a-second — A unit test runs in 10 to 100 ms against a pure core: no database, git repo, container, sleep or other program.
- §1.12 law-diagnose-before-you-buy-capacity — When a run suddenly takes longer, find the cause before changing a capacity knob: compare per-suite and per-phase timings of a fast pass and a slow one, file what you find, then choose between fixing the cause and buying capacity.
- §1.13 law-a-kit-mechanizes-the-sites-it-never-competes — Shared-platform code mechanizes the pattern its sites already run correctly; it never builds a parallel path beside it.
- §1.14 law-the-harness-switches-his-cockpit — Whatever puts a design, diff or report in front of Ryan switches his cockpit to it itself, every iteration; it never asks him to switch, and only he dismisses it.
- §1.15 law-calls-have-deadlines — Every request/response call (a query, a socket RPC, a CLI lookup) carries a client timeout of at most 5 s, and the receiver stops working 3 s after receiving it.
- §1.16 law-fix-the-harness-not-the-instance — Repair a harness-managed surface by changing the harness, never by hand-wiring the running instance: if the next refresh, rebuild or timer would undo your change, it is not a fix.
- §1.17 law-a-required-key-ships-with-the-change-that-needs-it — A change that makes a configuration key required ships the key in the same change: its spira/conf.d file, conf.key-history line and config-delta.toml entry, so activating the release adds it to the live config.
- §1.18 law-a-capacity-limit-is-fixed-at-its-consumer — Never add a late hard failure that refuses work for want of a resource — disk, memory, time — at the moment the work is about to run.
- §1.19 law-every-decision-biases-faster-or-safer — [Reserved]
- §1.20 law-a-landing-stop-is-reverted-first — When landing stops, revert the last change that landed before it, by hand, within 15 minutes, then diagnose.
- §1.21 law-diagnosis-is-time-boxed — Diagnosis is time-boxed to ten minutes; then act on the strongest hypothesis — eject, revert or roll back, all of which are cheap to undo.
- §1.22 law-bisect-by-time-first — When rounds fail regardless of their members, the cause is on main: look first at the last change that landed before the first failure, not at the members in the failing round.
- §1.23 law-the-direct-path-wins — If Ryan would do it in one terminal in N minutes, the Concierge does it in N or less; the mechanism that should have done it gets a bead afterwards, never first.
- §1.24 law-faster-over-safer — Every decision in the system biases toward faster over safer.
- §1.25 law-throughput-floor — When the beads landed across all repos over the trailing 24 hours falls below 150, the world is stopped, the root cause is analysed, and a solution is proposed to Ryan before anything else is worked.
- §1.26 law-batcher-earns-the-round-by-parity — A replacement for the round machinery cuts over with the world stopped, for every registered repo at once, once its 2026-10-31 replay passes in the simulator, its coverage gate passes, and one real round per repo lands on it; no shadow run and no per-repo handover.
- §1.27 law-tests-are-the-unit-of-measure — Spira measures tests, never suites.
- §1.28 law-bead-facts-come-from-the-lifecycle — Every fact about work has one owner and is read from it through spira-lc, never copied into the other plane.
- §1.29 law-a-tool-bounds-the-state-it-leaves — A tool that writes durable state — images, volumes, build targets, worktrees, clones, logs — bounds it: it removes what it superseded, or caps what it keeps, on its own path, every run.
- §1.30 law-a-measurement-ends-when-its-verdict-settles — A measurement runs until its verdict is settled, not for a round-number duration.
- §1.31 law-no-fallbacks — Nothing resolves a value by fallback: no default path, no inherited PATH, no search up from the executable, no second source tried when the first is missing.
- §1.32 law-a-unit-test-calls-no-binary — A unit test exercises library code in its own process and never spawns another binary, script or tool; one that must is a strongly justified exception, written beside it.
- §1.33 law-a-knob-is-set-inside-its-model — A question about a knob (a concurrency, a placement, a cap) is answered inside the model that governs it, never in isolation: state the model, show where today's facts contradict it, replace the model first if they do, and let the knob fall out of the new one.
- §1.34 law-periodic-work-is-incremental — A periodic job does only the work that changed since its last run, never a full redo of everything on each tick: back up new chunks, not the whole store; rescan what moved, not the whole tree.
- §1.35 law-a-migration-certifies-the-living-and-imports-the-dead-as-stored — A store migration certifies live records exactly and imports terminal history as stored.
- §1.36 law-a-stop-stops-everything — When Ryan says STOP, every running thing the Concierge started stops in the same turn: every builder and subagent, every detached job and chain, and the open round (stop its driver, abandon it with the reason, verify nothing is left running).
- §1.37 law-a-twice-failed-landing-is-traced-before-the-third — When a landing has failed twice, the third attempt is preceded by two read-only adversarial tracers — one on the VM path (the merged tree under the INSTALLED round-vm), one on the host landing and activation path — that predict the failures before they happen, each with file:line evidence and the preventive change.
- §1.38 law-text-only-changes-land-without-a-round — A change that touches only text — law/, statutes, wiki, docs, markdown — lands without a round: lint it on the host and land it with the lint as evidence.
- §1.39 law-list-reads-run-on-indexed-tables — A list operation reads an indexed table: the rows it returns are found by an index on the columns it filters and orders by, and the current version of a record is findable without scanning its history.
