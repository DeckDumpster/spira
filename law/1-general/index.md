# Part 1 — General

- §1.1 law-absence-needs-a-positive-control — A check that finds nothing must first prove it could have found something.
- §1.2 law-a-watcher-runs-the-sop-before-it-pages — A watcher that detects a condition runs the tool its matching SOP names, records the application, and reports the outcome; it escalates to the Concierge only what no runnable SOP covers, or what the tool could not settle.
- §1.3 law-a-failure-that-will-not-reproduce-is-a-fidelity-gap — A failure that repeats in a round or CI but passes in a reproduction means the reproduction is wrong.
- §1.4 law-p0-express-preempts-lanes — Maintenance work never holds capacity a P0 needs: while a P0 or express bead waits unclaimed, no reactive maintenance session that uses a bound resource class is called, and a waiting P0 express preempts the youngest running one through the stop path, which makes its bead true and loses nothing.
- §1.5 law-an-event-loop-never-blocks — An event loop never blocks: every blocking call it would make, file, socket, process, lock or sleep, is dispatched through a bounded queue to a bounded thread pool, and the loop only awaits the result.
- §1.6 law-a-reconciler-redrives-it-does-not-alarm — A reconciler redrives; it does not alarm.
- §1.7 law-a-p0-in-spira-itself-is-built-by-hand — A P0 defect in Spira's own machinery is built by the Concierge by hand and joins the very next round, cut at once with whatever is certified: it never waits for a batch to fill, and it never lands alone while certified work waits behind it.
- §1.8 law-operator-asked-transcript-reads-are-observation — The Concierge may read any live dwarf's session transcript read-only, asked or not: it is observation, like a status check.
- §1.9 law-doomed-work-is-stopped-fixed-then-resumed — Work the Concierge can see is doomed — a builder rebasing a member its open integration will redo, a round member whose tree cannot pass setup, a bead stacked on a parent that will not land first — is stopped at once: ejected from its round, or slain and held with a manual hold.
- §1.10 law-unit-tests-run-under-a-second — A unit test runs in 10 to 100 ms against a pure core: no database, git repo, container, sleep or other program.
- §1.11 law-diagnose-before-you-buy-capacity — When a run suddenly takes longer, find the cause before changing a capacity knob: compare per-suite and per-phase timings of a fast pass and a slow one, file what you find, then choose between fixing the cause and buying capacity.
- §1.12 law-a-kit-mechanizes-the-sites-it-never-competes — Shared-platform code mechanizes the pattern its sites already run correctly; it never builds a parallel path beside it.
- §1.13 law-the-harness-switches-his-cockpit — Whatever puts a design, diff or report in front of Ryan switches his cockpit to it itself, every iteration; it never asks him to switch, and only he dismisses it.
- §1.14 law-calls-have-deadlines — Every request/response call (a query, a socket RPC, a CLI lookup) carries a client timeout of at most 5 s, and the receiver stops working 3 s after receiving it.
- §1.15 law-fix-the-harness-not-the-instance — Repair a harness-managed surface by changing the harness, never by hand-wiring the running instance: if the next refresh, rebuild or timer would undo your change, it is not a fix.
- §1.16 law-a-required-key-ships-with-the-change-that-needs-it — A change that makes a configuration key required ships the key in the same change: its spira/conf.d file, conf.key-history line and config-delta.toml entry, so activating the release adds it to the live config.
- §1.17 law-a-capacity-limit-is-fixed-at-its-consumer — Never add a late hard failure that refuses work for want of a resource — disk, memory, time — at the moment the work is about to run.
- §1.18 law-a-landing-stop-is-reverted-first — When landing stops, revert the last change that landed before it, by hand, within 15 minutes, then diagnose; if the active release carries the breakage, roll it back.
- §1.19 law-diagnosis-is-time-boxed — Diagnosis is time-boxed to ten minutes; then act on the strongest hypothesis — eject, revert or roll back, all of which are cheap to undo.
- §1.20 law-bisect-by-time-first — When rounds fail regardless of their members, the cause is on main: look first at the last change that landed before the first failure, not at the members in the failing round.
- §1.21 law-the-direct-path-wins — If Ryan would do it in one terminal in N minutes, the Concierge does it in N or less; the mechanism that should have done it gets a bead afterwards, never first.
- §1.22 law-faster-over-safer — Every decision in the system biases toward faster over safer.
- §1.23 law-batcher-earns-the-round-by-parity — A replacement for the round machinery cuts over with the world stopped, for every registered repo at once, once its 2026-10-31 replay passes in the simulator, its coverage gate passes, and one real round per repo lands on it; no shadow run and no per-repo handover.
- §1.24 law-tests-are-the-unit-of-measure — Spira measures tests, never suites.
- §1.25 law-bead-facts-come-from-the-lifecycle — Every fact about work has one owner and is read from it through spira-lc, never copied into the other plane.
- §1.26 law-a-tool-bounds-the-state-it-leaves — A tool that writes durable state — images, volumes, build targets, worktrees, clones, logs — bounds it: it removes what it superseded, or caps what it keeps, on its own path, every run.
- §1.27 law-a-measurement-ends-when-its-verdict-settles — A measurement runs until its verdict is settled, not for a round-number duration.
- §1.28 law-no-fallbacks — Nothing resolves a value by fallback: no default path, no inherited PATH, no search up from the executable, no second source tried when the first is missing.
- §1.29 law-a-unit-test-calls-no-binary — A unit test exercises library code in its own process and never spawns another binary, script or tool; one that must is a strongly justified exception, written beside it.
- §1.30 law-a-knob-is-set-inside-its-model — A question about a knob (a concurrency, a placement, a cap) is answered inside the model that governs it, never in isolation: state the model, show where today's facts contradict it, replace the model first if they do, and let the knob fall out of the new one.
- §1.31 law-periodic-work-is-incremental — A periodic job does only the work that changed since its last run, never a full redo of everything on each tick: back up new chunks, not the whole store; rescan what moved, not the whole tree.
- §1.32 law-a-migration-certifies-the-living-and-imports-the-dead-as-stored — A store migration certifies live records exactly and imports terminal history as stored.
- §1.33 law-a-stop-stops-everything — When Ryan says STOP, every running thing the Concierge started stops in the same turn: every builder and subagent, every detached job and chain, and the open round (stop its driver, abandon it with the reason, verify nothing is left running).
- §1.34 law-a-twice-failed-landing-is-traced-before-the-third — When a landing has failed twice, the third attempt is preceded by two read-only adversarial tracers — one on the VM path (the merged tree under the INSTALLED round-vm), one on the host landing and activation path — that predict the failures before they happen, each with file:line evidence and the preventive change.
- §1.35 law-text-only-changes-land-without-a-round — A change that touches only text — law/, statutes, wiki, docs, markdown — lands without a round: lint it on the host and land it with the lint as evidence.
- §1.36 law-list-reads-run-on-indexed-tables — A list operation reads an indexed table: the rows it returns are found by an index on the columns it filters and orders by, and the current version of a record is findable without scanning its history.
- §1.37 law-list-reads-paginate-in-the-database — A list operation paginates in the database, never in the application: its limit, cursor and filters are part of the query, so a page costs a page.
- §1.38 law-a-hand-dispatched-p0-builder-runs-under-a-watcher — A builder dispatched by hand on a P0 runs under a live, read-only watcher that reads its transcript as it works and stops on the first leading indicator of a wasted run — a write verb probed for usage, production config in a test shell, a failing command repeated, a test edited to pass, a fix that moves a cost instead of removing it, green claimed from a partial run — so the steer arrives in minutes, not after the round.
- §1.39 law-a-blinded-operator-surface-is-p0 — A defect that blinds an operator surface — the ops pane, the asks pane, a status briefing's facts — is P0 whether or not the loop is still moving: the operator steers by that surface, and a loop he cannot see is one he cannot stop in time.
- §1.40 law-a-loops-hot-read-is-in-process — A core process of the loop reads lifecycle, round and config state in-process through the store's and config's libraries, never by spawning another Spira binary or a shell bootstrap: a spawned read pays a whole start-up for one answer, so a probe that forks forty times a minute turns a 40 ms lookup into a second.
- §1.41 law-landing-rounds-run-the-full-suite-on-a-vm — A landing round lands only when every suite has passed on a round VM against an input closure identical to the landing tree's: a verdict is keyed per suite by the inputs the test plan says it reads, never by the whole tree, so an eject or re-cut re-runs only the suites whose inputs changed; an uncomputable closure re-runs.
- §1.42 law-a-landing-stall-starts-a-repair — When a repository has landed nothing for two hours while beads sit SUBMITTED or IN_DELIVERY there, a diagnosis-and-repair incident is filed at once, express and P0, for the ops lane to root-cause and fix, and the Concierge is paged once.
- §1.43 law-a-round-loser-is-fixed-and-landed-by-hand — When a harness defect is losing landing rounds, the Concierge fixes it now: it traces the cause itself, hands a directed dwarf the exact change, and lands the result by hand on targeted evidence the moment it is built.
- §1.44 law-a-page-is-looked-at-then-the-issue-or-the-detector-is-fixed — Every page is looked at when it arrives, by whoever receives it, whatever its class and however often that class has been false.
- §1.45 law-the-lifecycle-store-serves-online-data — The lifecycle store serves online data: open work and a bounded recent window of closed work.
- §1.46 law-only-spira-lc-talks-to-the-stores — Nothing but the store server runs bd, bd-embedded, bdq or dolt, or opens a SQL connection to the store: no crate, script, hook, test fixture, persona or session, under any path.
- §1.47 law-gates-run-in-a-clean-environment — A gate, check or test invoked by automation must run in an explicit minimal environment, never the caller's.
- §1.48 law-a-round-lost-without-cause-stops-the-rounds — When a round is abandoned or voided while no member was red, the round machinery stops, owned by the Concierge, only for as long as it takes to name the cause from the round record and put a builder on its fix: ten minutes.
- §1.49 law-every-bead-is-written-or-reviewed-by-skuld — Every bead is written by Skuld or reviewed by Skuld before it is filed, whoever files it; a body no Skuld pass has seen is not filed.
- §1.50 law-every-decision-passes-the-statute-check — Every decision by every actor passes the statute check before it is made: filing or amending a bead, writing a design into one, answering or escalating an ask, ejecting or attributing a red, changing a config value.
- §1.51 law-check-the-law-at-the-decision — A dwarf checks the law at the decision it governs.
- §1.52 law-a-bead-reference-carries-its-details — Any message that names a bead carries that bead's details with it — title, status, priority, and the one fact the reader needs to act.
- §1.53 law-a-bead-title-omits-its-repo — Every bead is filed with its repository as a required, explicit field of the filing facade, on every filing path, with no default, and every surface that renders a bead shows the repository from that field.
- §1.54 law-a-beads-priority-is-a-floor — Among work not yet started, a bead's own priority is a floor in every selector that orders or admits it: claim ranking, round selection, batching, admission.
- §1.55 law-a-binary-resolves-the-config-it-reads — A binary or shim that needs configuration conf.sh resolves must resolve it itself, in-process through spira-config, never read it from its own environment: almost nothing conf.sh resolves is exported, and a unit starts a binary with only SPIRA_RELEASE and PATH.
- §1.56 law-a-broken-prod-surface-is-fixed-by-hand-first — When a production surface is visibly wrong and a reversible operational action repairs it, the Concierge does that action at once (backup first, then verify on production) instead of filing a bead and waiting on a delivery cycle.
- §1.57 law-a-budget-is-a-cutoff — A time budget is enforced, never advisory: when a stage has one, the stage stops at it.
- §1.58 law-a-bug-with-a-fix-in-flight-depends-on-it — When a bug a person filed already has a fix in flight, neither close it nor leave it ready: make it depend on the fixing bead, so it leaves the queue and returns as the check on the fix.
- §1.59 law-a-builder-bead-names-what-to-build — A builder is handed only a bead that names what to build: the deliverable, component or change, and where.
- §1.60 law-a-cap-breach-is-acted-on-not-explained — A monitor line past a hard cap is a breach, not a datum: the run is killed at the cap by the machinery itself, with a named over-cap red naming the phase, and what overran is fixed.
- §1.61 law-a-catchup-targets-a-fixed-point — A bead never aims at a moving target.
- §1.62 law-a-check-reports-every-unit — An expensive check reports a verdict for every independent unit it ran, never only the first failure or a summary that discards the rest.
- §1.63 law-a-component-reports-what-it-observed — A component reports what it observed, never the cause it infers: a refused or absent socket is "not running", not "restarting", and no caller branches on a lifecycle state of another component that it cannot observe.
- §1.64 law-a-concierge-duty-is-a-missing-mechanism — Anything the Concierge does by hand to keep the loop moving is a mechanism the harness lacks: codify it as a tool, a watcher row or a persona that owns it, never as a habit of whoever is at the keyboard.
- §1.65 law-a-concurrency-ceiling-names-its-measurement — A concurrency ceiling (live dwarves, gate slots, certify width, round size) is set only with the measurement that justifies it and the condition that retires it, recorded beside the value; when that condition is met the ceiling is re-measured, never left standing on a reason that has passed.
- §1.66 law-a-config-value-has-no-fallback — A config value has one definition and no fallback: the registry declares it, the shipped spira.toml carries it, every reader takes it from spira-config, and a missing key is refused by name rather than defaulted.
- §1.67 law-a-control-that-cannot-check-must-refuse — A control that cannot perform its check must refuse, not warn and proceed.
- §1.68 law-a-cutover-is-certified-per-path — A cutover is certified only on the paths it was run on.
- §1.69 law-a-cutover-takes-downtime — A component that replaces an existing authority is built and launched inert; then one batch cuts every caller over while the data migration runs, and the system takes downtime — stop and drain — rather than carrying two authorities, dual writes, a shrinking allowlist or a drift report to keep the old path alive.
- §1.70 law-a-delegated-study-starts-from-the-brain — Before delegating a study, audit or review of an area, the delegating agent searches the brain wiki for what is already written on it and names those pages in the brief, with the levers they already propose; an agent that re-derives an area from the code alone ranks only what the code makes visible and misses a lever the brain already holds.
- §1.71 law-a-deliberate-state-is-not-a-fault — A state the operator chose must never render as a fault.
- §1.72 law-a-design-for-approval-reaches-his-phone — A design put to Ryan for approval is published where he can read and comment on it from his phone — a Claude Doc linked directly under the design page's title — and in the same act its approval ask is filed, naming the defaults, so the decision reaches him as mail.
- §1.73 law-a-design-prices-what-it-rejects — A design that rejects an alternative states its cost in measured or explicitly estimated numbers — what it covers and misses, what must be installed and where, what config must be written, the ongoing cost — and never dismisses it with an adjective.
- §1.74 law-a-design-time-is-a-goal-not-an-assertion — A time figure in a design or a bead's acceptance - land in under 60 s, answer in under 500 ms - is a goal the system is measured against, never an assertion a test makes.
- §1.75 law-a-designation-is-never-derived — A scarce designation — express, urgent, exempt — is granted only by an explicit request, never inferred from another field.
- §1.76 law-a-detector-files-a-bounded-batch — A check that files work items caps how many it files in one pass and logs what the cap held back.
- §1.77 law-a-dismissal-names-its-cover — An actor who calls an alarm, a red or a slow reading already covered names the open bead that covers it, found with `work search` before saying so; with no open bead it files one through `work file` or tells Ryan plainly that nothing covers the condition, never calling it routine.
- §1.78 law-a-documented-control-must-exist — Never write a document that asserts a control no program enforces.
- §1.79 law-a-duplicate-close-moves-the-deliverable — Closing a bead as a duplicate first moves the closed bead's deliverable and acceptance onto the survivor, as a note or a child, so no fix loses its home.
- §1.80 law-a-failure-carries-its-own-explanation — A harness that reports a failure must carry that failure's own explanation.
- §1.81 law-a-fallback-has-a-forced-mode — Every automatic fallback ships a no-fallback mode and a cheap check of its primary path, wired to a watcher, so a broken primary is red within minutes instead of hidden behind the fallback that absorbs it.
- §1.82 law-a-flipping-test-is-disabled-by-a-registry-row — A test that fails then passes on an unchanged tree is disabled in the same round by a test-registry row, for seven days, on a bead that fixes it or replaces it with a deterministic test; it is not retried.
- §1.83 law-a-forked-sibling-diverges-only-by-decision — A repo forked from a sibling (dumpstar from pokedumpster) diverges from it only by decision.
- §1.84 law-a-gate-closes-on-the-reply — A bead that exists to wait on Ryan's answer closes only when his answer is on record: his verdict on the ask, or his mail reply.
- §1.85 law-a-guard-refuses-it-does-not-tidy — When a rule reaches rung four, the mechanism refuses at the point of violation.
- §1.86 law-a-hand-fix-names-its-root-cause — Every repair you make by hand cuts a bead for the defect that made it necessary, in the same session, before you move on.
- §1.87 law-a-hand-substitute-never-satisfies-the-duty — A hand substitute never satisfies the duty it stands in for: when a persona runs by hand what a mechanism owns, the mechanism's silence is an incident the same hour, and every result the hand run reports says it is a substitute.
- §1.88 law-a-known-red-preempts-the-pass — A pass's reds are watched as they land, not read at its end.
- §1.89 law-a-lane-runs-only-where-the-repo-admits-it — A persona may cut work only against a repository whose lanes admit that persona.
- §1.90 law-a-lane-spills-over-the-ceiling — Reactive work never waits for planned work: when a bound resource class is at its limit and a reactive session that uses it has demand, it starts above the limit, and the class drains by attrition: no planned session starts there while its live count, reactive sessions included, exceeds the limit.
- §1.91 law-a-learned-failure-mode-becomes-a-state — When a failure mode is understood, model it in the lifecycle: add the state, the event and the valid transitions that name it, so the machine records it, refuses what it makes illegal, and every view can show it.
- §1.92 law-a-lesson-applies-to-every-queue-mode — A landing-path lesson learned on one queue mode is owed to every mode — VM rounds, forge batches, pr, push and local alike.
- §1.93 law-a-load-red-waits-on-a-signal — A test red only under the full-corpus run and green at low load is repaired by waiting on a signal the code under test emits, with a generous cap, never by widening a timing window; where no signal exists, the code gains one or the case is deleted.
- §1.94 law-a-local-green-names-what-it-missed — Before offering a round as a PR, enumerate its known divergences from the gate's environment — toolchain and lockfile, suspended or SKIPPED units, CI-only steps — close what you can, and state what the local green does not cover.
- §1.95 law-a-lost-verified-result-is-data-loss — A completed verification that the system then discards or cannot record (a green certification, a passed gate, a finished acceptance) is a P0 data-loss incident, not a retry cost: the round or bead is landed from the existing evidence or the defect that lost it is fixed first, it pages as P0 until resolved, and re-running the verification is never reported as costless.
- §1.96 law-a-matcher-reads-code-not-prose — A check that greps a file for a mechanism must read a comment-stripped view of it, and must fold line continuations first.
- §1.97 law-a-money-ceiling-binds-only-in-steady-state — A money ceiling binds a system in steady state and never one in bring-up: while a capability is still being proved, spend what the task needs, report what it cost in the same message, and restore the ceiling when the operator calls it steady.
- §1.98 law-a-pattern-match-is-not-an-identity-check — A grep is a substring match, not an identity check.
- §1.99 law-a-pause-releases-itself — A pause, drain or hold that a session or tool sets names its owner and its release condition, and lifts only on that condition or by an explicit act.
- §1.100 law-a-pipeline-builds-each-artifact-once — A pipeline builds each artifact once.
- §1.101 law-a-provisional-member-leaves-on-its-gate-red — A round takes CERTIFIED beads first and adds unheld SUBMITTED ones before their gate finishes; those members are provisional and recorded as such.
- §1.102 law-a-published-design-carries-its-ask — A design published for Ryan's review carries its approval ask in the store from the moment it is published, blocked on nothing, with the Concierge's recommended answer as its default.
- §1.103 law-a-questioned-statute-stays-in-force — A statute in the book is in force until it is retired.
- §1.104 law-a-rebase-loop-is-sequenced-not-split — A bead re-conflicting on rebase is a race on a hot file, not an oversized bead: never split it or escalate it.
- §1.105 law-a-red-run-report-closes-on-its-fixes — A bead whose whole content is a report that a run was red closes as no-code-change as soon as every failure it names has its own fix bead, citing them in the close reason; it never waits for a later green run, and it never asks the operator for permission to close.
- §1.106 law-a-refusal-is-not-an-undo — A rejected or interrupted tool call may already have run; the refusal stops the next call, not the side effects of the one in flight.
- §1.107 law-a-refusal-names-its-exit — A check that blocks a legitimate operation must name, in its own refusal message, why it refused and the sanctioned way through: an input, a flag or a named procedure that records who claimed the precondition and on what evidence.
- §1.108 law-a-regression-test-must-be-seen-to-fail — A regression test is not written until it has been run against the UNFIXED code and seen to fail.
- §1.109 law-a-release-passes-acceptance-on-its-tag — Never call a release clean, or hand it to another install, until end-to-end acceptance has passed on that exact tag.
- §1.110 law-a-remainder-is-not-a-cap — A number that already nets out what is running is a REMAINDER, not a cap.
- §1.111 law-a-rename-repoints-no-reader — Renaming a systemd unit repoints nothing that reads its name.
- §1.112 law-a-repo-is-defined-in-its-own-terms — A repository's code, docs and checks are written in its own domain's terms and never name another repository or product, not even to forbid it: a check that lists a sibling's vocabulary couples the two repos and defines one's correctness by the other.
- §1.113 law-a-report-is-not-a-filing — A finding exists only where something will surface it: an open bead, an insight, or an ask in the operator's pane.
- §1.114 law-a-restart-is-bounded-not-avoided — A service restart that an activation or deploy performs is kept, because a restart on every activation is the cheapest smoke test there is; its cost is bounded instead.
- §1.115 law-a-retry-must-change-an-input — A retry that changes nothing is not a retry, it is a loop.
- §1.116 law-a-reversal-is-announced-as-one — Reversing something you told Ryan you would or would not do is news in its own right: say 'I am reversing X because Y' as the lead of its own message, before acting, never as a clause inside a status line.
- §1.117 law-a-reversal-is-written-where-the-ruling-is-quoted — When an order reverses a decision already closed, record the reversal on the closed decision bead and on every open bead whose notes quote its answer, before any builder is launched against them.
- §1.118 law-a-review-outlives-its-session — A design review in Ryan's hunk pane outlives the session that opened it.
- §1.119 law-a-round-is-feature-first-then-catch-all — Never let submitted beads idle without a round running.
- §1.120 law-a-round-lands-only-on-a-green-pass — A round lands only on a pass with no red.
- §1.121 law-a-runner-takes-a-list — A runner takes an explicit list of what to run; whatever decides which — a diff, a tag, a full-corpus flag — is a separate program printing names on stdout.
- §1.122 law-a-second-defect-gets-its-own-bead — A hand-fix for a defect other than the bead's own defect gets its own bead, even on the release path; the rule against filing off the release path covers investigation and nice-to-haves, not a second defect found and fixed.
- §1.123 law-a-secret-never-travels-through-the-transcript — A secret never passes through the chat or any transcript.
- §1.124 law-a-shared-runner-image-is-general-purpose — A runner image shared across repositories carries only general-purpose substrate (OS, runner, container engine, toolchain).
- §1.125 law-a-split-repoints-nothing — When one repository, database or path is split in two, every variable naming the old shared location goes on resolving and starts meaning the wrong thing.
- §1.126 law-a-statute-names-its-tool — A statute that prescribes an action names the tool that performs it, or is enacted with the bead that builds it; an actor whose only legal tool cannot comply says so and files that tool at P0, never doing just what the tool allows.
- §1.127 law-a-statutes-silence-is-not-permission — A statute's silence is silence, not permission.
- §1.128 law-a-store-write-is-not-a-delivery — A write to the bead store is not a delivery.
- §1.129 law-a-summary-request-gets-the-data — A request for a summary, report or 'how did X go' is answered with the data and where it lives: the source file or query, the numbers (counts, medians, before and after), and the raw rows when there are few.
- §1.130 law-a-sweep-is-not-a-bead — A periodic check is not a unit of work.
- §1.131 law-a-target-closes-only-met-or-contradicted — A bead that names a target closes only when the target is met, shown by the measurement it names, or contradicted, shown by evidence that it cannot be met as stated.
- §1.132 law-a-test-never-builds-spira — There is only one way to build Spira, and builds are not tested: cargo build has no place in a test.
- §1.133 law-a-tested-tree-is-not-retested-on-push — A push to a landing branch whose tree a pull request's CI already passed is not re-tested on push: the push run checks that the tree is the one the PR run tested and records the skip, naming the PR and run.
- §1.134 law-a-tool-needs-a-runner — A tool only a session at the keyboard runs is still a hand.
- §1.135 law-a-wait-names-what-it-waits-for — A wait or barrier names what it waits for — the beads, runs, processes or signal — and its duration is only a cap on that wait, never the condition.
- §1.136 law-a-watcher-asks-the-component-that-decides — A watcher that reports work is due obtains that judgement from the component that performs the work, never re-derives it from raw state; where no such query exists, add one and have both call it.

- §1.199 law-detect-drift-never-install — A harness check may DETECT that what is installed has drifted from its source; it may not repair the drift.

- §1.296 law-periodic-tool-needs-a-tested-timer — A tool meant to run periodically is not done when the script works.
- §1.297 law-pin-by-migration-count — A binary's version string does not order against a release tag: a build from main knows MORE schema migrations than a tagged release.
- §1.298 law-prefer-no-comment — Prefer no comment.
- §1.299 law-prefer-the-real-dependency — Test against the real dependency on a throwaway instance, not a hand-written model of it.

- §1.304 law-product-aws-resources-live-in-the-ci-account — A product's AWS resources (its live data stores such as a lake bucket, as well as its off-box backups) are created in the CI account, through Terraform and the terraform-deploy role under a per-product name prefix, unless Ryan names another account for that product.

- §1.307 law-publish-ci-runs-the-full-suite — A publish PR's CI runs every suite, never the selection its diff picks; what reaches main has passed the full suite on CI's VM, as every landing round has on the round VM.
- §1.308 law-query-the-graph-before-asserting — Never report the state of a repository dwarves are working without first querying the graph for it.
- §1.309 law-query-the-graph-before-working — Before doing work by hand or filing work to be built, query the graph for a bead that already owns it: work list filtered on the words of the deliverable (not the title you chose), and spira-lc list for what is WORKING.
- §1.310 law-queue-back-pressure-is-an-open-pr — Under queue.forge the merge queue's only back pressure is whether a batch PR is open: cut when none is, land when that PR's own gate is green.
- §1.311 law-raise-the-cap-before-you-optimize — When a resource cap (a VM's memory, a runner's size, an instance type, a concurrency limit) blocks a path that has never yet run end to end, raise the cap to whatever makes the path run and file the reduction as separate later work; do not make the consumer leaner first.
- §1.312 law-read-the-manual-first — Read the manual before probing, and before theorising.
- §1.313 law-read-the-servers-own-log-first — When a component fails, read its own log before forming any hypothesis, and state no cause to Ryan, nor ask him to act on one, until you have watched the failure with your own instrument: the failing step's log line, a trace naming the sender, or the fault reproduced and then absent.
- §1.314 law-read-what-you-launched — Every check, probe, re-run or dispatch launched to answer a question is finished only when its output has been read and what it said reported, in the session that launched it.
- §1.315 law-reading-his-accounts-is-a-permissions-ask — Work that gives an automation read access to the operator's personal accounts (order history, mailbox, calendar, statements, any record of what he did outside the system) is escalated as a permissions ask and built only on his answer, and what such a read finds may never relax a limit the automation enforces on itself.
- §1.316 law-record-the-act-only-on-the-act — Never sequence the record of an act behind the act with a semicolon.
- §1.317 law-reduce-the-count-never-throttle-the-job — When the box congests, lower the number of concurrent workers — dwarves, agents, gate slots — and let each run at full speed.
- §1.318 law-regenerate-derived-summaries — Rewrite a derived document — a one-pager, crib sheet, exec summary or dashboard view — from scratch on every update rather than editing it in place as new findings land.
- §1.319 law-remeasure-after-you-change-it — A measurement taken before a fix says nothing about the system after it.
- §1.320 law-repeating-conditions-escalate-once — A condition that stays true escalates once.
- §1.321 law-replace-running-scripts-atomically — Never rewrite a harness script in place while a process may be executing it — bash reads a script by byte offset as it runs, so an in-place write (an editor save, python open(p,'w'), sed -i) shifts the bytes under a running dwarf, sentinel or landing pass and it resumes parsing mid-text when its current command returns.
- §1.322 law-reply-in-the-thread — Answer Ryan where he asked.
- §1.323 law-reproduce-acceptance-locally-before-remote — Where the only real run of a path is an expensive remote attempt — acceptance, a release, a CI round — reproduce the failure locally on a throwaway instance and show the fix green there on the exact tree before spending the attempt, for every phase.
- §1.324 law-require-the-right-value — When a wrong or missing value keeps appearing at an interface, fix it by making the right value a required, obvious field of the facade that every caller goes through, with no default, so the easy path is the correct one; do not add a refusal that pattern-matches the wrong value downstream.
- §1.325 law-resolved-operator-mail-is-cleared — Operator mail whose question is answered, enacted or moot is cleared from his mailbox without asking him, so the mailbox count alone answers what is waiting on him; clearing archives, never deletes, so the dismissal sweep cannot read it as a default taken.
- §1.326 law-retire-dont-suspend — A subsystem nobody wants running is deleted, not suspended.
- §1.327 law-reversibility-outranks-coverage — Reversibility outranks test coverage.
- §1.328 law-reversible-only-with-infrastructure-credentials — An agent holding infrastructure credentials performs only reversible operations: clone, configure, mask, start, stop, convert.
- §1.329 law-review-reads-the-raw-transcript — A review of a session's own conduct, and any agent briefed to reconstruct what a session did or built, reads the raw transcript (the JSONL of user messages, assistant text, tool calls and tool results), never the session's compaction summaries or its own reports; where a summary and the raw events disagree the raw events win, and a summary is never cited as evidence.
- §1.330 law-run-it-once-before-you-decompose — Before decomposing work whose premise is that something is broken, run the thing once and read the result.
- §1.331 law-run-the-suite-in-a-container — Run every suite inside a rootless-podman container holding a real install of the candidate, by default — not only where a fake fixture already hurts.
- §1.332 law-rust-rewrite-order — Finish the harness's move to Rust by what the loop hurts on, not by size: the gate and its fences first, then rounds, verdicts and delivery, then test infrastructure; conf.sh and lib.sh last, emptied by moving each function family into the crate that already calls it.
- §1.333 law-rust-rewrites-start-from-intent — A rewrite into Rust starts from what the old code was FOR, never from its lines.
- §1.334 law-rust-then-java — For new side-project code, default to Rust; Java is the fallback where JVM ecosystem integration is genuinely required.
- §1.335 law-schema-over-code — Lean on the data substrate before writing a rule into a tool.
- §1.336 law-scope-is-a-runtime-key — What the fleet may work on is a runtime key, never a literal in the source.
- §1.337 law-seen-red-must-be-seen-in-ci — A test that asserts a bug REPRODUCES measures the machine as much as the code, so it is not done until CI has run it green at least once.
- §1.338 law-self-filing-earns-its-priority — Machinery that files a bead about the machine files it at P3 unless it can name something broken for a user, and a report arriving from outside enters above it.
- §1.339 law-settable-in-the-operators-words — A setting the operator names in plain terms must be settable in those terms.
- §1.340 law-setup-never-outlasts-the-suite — A setup step never takes longer than the suites it serves.
- §1.341 law-ships-for-a-colleague — Nothing Spira ships may name an operator, a machine, or one box's paths — those are config keys with defaults, and comments address the operator, never a person.
- §1.342 law-sops-are-amended-by-the-session-that-found-the-gap — An Ops session that matched an SOP and found it incomplete amends it in that same session, before closing.
- §1.343 law-spira-does-not-deploy — Spira builds, gates and lands work; it never deploys a product.
- §1.344 law-spira-reaches-prod-only-through-a-release — The machine that develops Spira never runs it in production from the tree it is edited in.
- §1.345 law-stale-red-pr — Before diagnosing a red PR, check whether it is behind master.
- §1.346 law-state-is-never-read-from-text — Decide any object's state or status — bead, round, batch, hold, ask, unit, release, mail — only from a typed value: an in-process typed API, a command's JSON answer deserialised into a struct, or an exit code mapped to an enum.
- §1.347 law-status-after-a-pipe-is-the-last-command — The exit status after a pipeline belongs to the LAST command in it, so reading it after piping into head, tail, grep or sed reports the pager's status and never the program's.
- §1.348 law-stop-the-bleeding-before-fixing — When a defect is actively consuming dwarves, tokens or money, stop the world FIRST and fix it second.
- §1.349 law-stop-the-world-for-an-unexpected-bottleneck — When a bottleneck appears that you did not expect, stop the world, fix it, and show it is fixed permanently before resuming — never work around it while the loop keeps running, and never let open beads pull attention off the goal in progress.
- §1.350 law-take-the-simple-fix-with-a-meter — When two fixes are both correct and one is simpler, take the simpler one AND land the measurement that will say when it stops being adequate — in the same change, never as a follow-up.
- §1.351 law-test-selection-and-plan-are-one-source — Test selection, the test plan and its coverage documentation derive from one source, so no merge can make one disagree with another.
- §1.352 law-test-statute — A test statute text.
- §1.353 law-tests-run-only-through-testenv — Suites run only through testenv, in a container; never on the host, whether from a worktree, the gate or by hand: a host run proves nothing about the candidate and can reach the real box.
- §1.354 law-the-allocator-assigns-the-identifier — Never choose an identifier an authority can assign.
- §1.355 law-the-concierge-drives-rounds-with-the-batchers-tools — The Concierge and the batcher cut, certify, eject and land a round through the same sanctioned tools, which record the round as a batch on the lifecycle machine.
- §1.356 law-the-concierge-rotates-through-the-tool — The concierge is one conversation at a time, reachable from desk and phone: one claude process in the concierge tmux socket with Remote Control.

- §1.359 law-the-harness-checkout-is-production — The harness checkout is production.
