# §1.59 law-a-builder-bead-names-what-to-build

A builder is handed only a bead that names what to build: the deliverable, component or change, and where. A bead that states only a problem or an outcome is design work; it goes to a spike for a build spec, approved as a design decision, before any builder sees it. Scar: given only 'deploys must not fail requests', a builder chose the mechanism itself and put a Python proxy in a Rust repo.
