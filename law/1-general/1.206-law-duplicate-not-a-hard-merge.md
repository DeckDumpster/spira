# §1.206 law-duplicate-not-a-hard-merge

A rebase that conflicts on code already present on the base branch means the bead is a DUPLICATE, not a hard merge. Diff it against the base file by file, salvage only what is genuinely absent, then retire it with 'bd supersede <id> --with <successor>' — never a close reason alone, which the sentinel does not read, so it reopens the bead as closed-without-landing. Delete the branch. Never re-apply the duplicate half; that reverts the version under test. sp-dvlq spent seven attempts rebasing sp-35pl's landed fix.
