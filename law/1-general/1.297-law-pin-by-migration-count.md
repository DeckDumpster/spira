# §1.297 law-pin-by-migration-count

A binary's version string does not order against a release tag: a build from main knows MORE schema migrations than a tagged release. Establish fitness by migration count and pin it, never by version. The discriminating check is `bd migrate schema` — exit 0 with 'already at vN' means fit; `--version` tests nothing. Never roll a database cursor back to match a binary; rebuild the binary and remove the wrong one. Scar: v1.2.2 (53 migrations) read as newer than 1.1.0-dev (61), producing four rollback escalations and one rollback that broke every production write until reverted three minutes later.
