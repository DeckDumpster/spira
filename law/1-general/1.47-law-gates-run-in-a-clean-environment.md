# §1.47 law-gates-run-in-a-clean-environment

A gate, check or test invoked by automation must run in an explicit minimal environment, never the caller's. Ambient configuration silently decides verdicts: a sentinel exporting its rune list passed it through systemd into a test suite asserting defaults, so correct work was rejected and would have been rejected on every retry until the bead poisoned, presenting as a failing bead with nothing pointing at the environment. Pass what the check needs and nothing else. Build output is not environment: a unit gate may build in the submitting builder's build directory, where cargo's fingerprints decide what is reused and the round stays the independent check (sp-3ps1pd).
