# §1.568 sop-verdict-repeat-refused-nochange

MATCH: Repeat attempt refused|repeat attempt: no change
SYMPTOM: Verdict gate refuses a repeat attempt because the branch has no new commit since the last attempt.
CHECK: grep -E 'Repeat attempt refused|repeat attempt: no change' /tmp/<bead>.payload ; then compare the "Red suites" named across the bead's recurrence notes.
FIX: If the SAME suite is red each time: commit a real fix, or rerun with SPIRA_VERDICT_REPEAT_CONSIDERED=<reason> once you have verified the reason. If the red suite DIFFERS per recurrence (e.g. cert-sweep/tip: sentinel-pass, install-dolt-ready, install-hooks-artifact over 21 recurrences) it is load-dependent flakiness, not a defect: do not override unverified and do not re-attempt; run each named suite in isolation via testenv on the tip, and file a builder bead per suite that fails when isolated (work file --for builder), or the batcher bead for the load cause if all pass.
ESCALATE: if the reason cannot be stated, the work is not understood; file a bead instead of overriding. Recurring on one branch with rotating suites: the alert is measuring load, not code.
