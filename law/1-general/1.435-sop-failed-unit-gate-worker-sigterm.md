# §1.435 sop-failed-unit-gate-worker-sigterm

MATCH: FAILED UNIT: spira-gate-worker-prod\.service.*(status=15/TERM|Failed with result 'signal')
SYMPTOM: spira-gate-worker-prod.service "failed" with Main process exited code=killed status=15/TERM, Failed with result 'signal', after a short run with high CPU. No error line from the worker itself; podman batch containers cleaned up normally.
CHECK: journalctl --user -u spira-gate-worker-prod.service -n 60 | grep -E 'status=15/TERM|Starting|Stopped' ; SIGTERM + 'Stopped' right after means an external stop/restart (deploy, timer re-fire, operator), not a worker crash.
FIX: Nothing to repair if the unit is active again or inactive-by-design. Confirm with systemctl --user is-active (needs XDG_RUNTIME_DIR). If it recurs without a deploy, find who sent the TERM (journalctl for systemctl stop/restart around the timestamp) and file a builder bead to make the watcher ignore signal-stops (a SIGTERM is a deliberate stop, law-a-deliberate-state-is-not-a-fault).
ESCALATE: if the gate worker is stuck stopped while branches are queued for gating.
